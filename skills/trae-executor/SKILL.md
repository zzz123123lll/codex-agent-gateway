# TRAE 桌面执行

Codex 负责目标、约束与验收，TRAE 使用自己桌面会话的模型、工具和技能执行。网关必须运行并安装桌面连接组件；单独安装 Skill 不能建立连接。

- 用 `agent_hub_submit`，明确 `provider: trae`、业务项目的绝对目录、目标、授权修改范围和验收条件。新提交使用稳定 `idempotencyKey`，保存返回的 `hub-…` 编号。
- 用 `agent_hub_wait` 作不超过50秒的有界等待；状态不变时继续等待原任务。已有编号先 get/wait，不因断线、工具未加载或等待超时重复提交。大成果留在文件里。
- `completed` 只表示原生执行结束且结果格式通过。独立检查真实文件、关键来源或相关测试后，用 `agent_hub_accept` 保存具体 note/evidence；不要用非空文件或执行器自述代替验收。
- 需要修改时用 `agent_hub_rework` 集中写明问题和改好标准。它沿用原生 session，生成新轮次和新结果文件。只有确认上轮停止后才返工。
- 用户要求完成项目时，在现有授权范围内持续执行“TRAE 交付 → Codex 独立检查 → 具体返工 → 复验”；不要每轮停下来要求用户确认。先确定可验证的功能、边界和回归标准；执行器报告完成后必须检查真实成果。
- 每次返工包含问题编号、具体文件或位置、实际行为、重现方法或证据、期望行为、允许修改范围及复验要求。集中反馈本轮已发现的问题，保留同一个任务编号与原生会话；记录每轮失败证据，不能用新结果覆盖旧验收记录。
- 修复后重新检查所有本轮问题，并运行与修改有关的回归检查。只有明确标准全部通过且无未解决的阻塞缺陷时才 accept；记录检查方法、实际结果、轮次和限制。已验收成果发现新问题时也可 rework，原验收属于旧轮次。
- 连续两轮同一问题没有实质进展时先诊断根因、缩小修复任务并调整指示；仍不能前进或遇到权限、环境阻塞时保留未通过状态与具体原因。不要无限重试、降低标准、伪造通过，也不要仅按固定轮数自动验收。
- `uncertain` 或仍有 `holdsCapacity` 的阻塞不可重发。检查原生会话及现有成果；必要时使用网关的人工检查恢复入口，并记录原因。取消请求不代表已停止。
- 委派不扩大用户授权。不由 Codex 代写委派成果或把自己的工具动作当作 TRAE 的执行证据。缺登录、项目信任或原生权限时说明具体原因，沿用 TRAE 的审批流程。
- 模型沿用 TRAE 设置，用量未知，不承诺积分节省或与独立 TRAE CLI 共用额度。桌面内部命令升级后须重新验证。

没有 MCP 工具时，可在完整网关目录运行 `node dist/cli.js submit @task.json`、`get 编号`、`rework 编号 修改意见`、`accept 编号 evidence.json`。MCP 配置与安装见完整项目 README。
