# 架构

## 模块责任

|目录|责任|
|---|---|
|domain|严格输入契约、任务状态、公开类型和异常|
|application|串行调度、容量与工作目录互斥、执行身份协调、返工和验收|
|infrastructure|兼容 SQLite 存储、文件摘要和路径边界、WorkBuddy 原生连接与执行适配|
|transport|HTTP 路由、鉴权、长轮询和事件流、SDK、MCP、工作台|
|runtime|服务配置、锁、令牌与原子连接文件、启动失败清理和停止|
|platform|保持旧导入路径的兼容入口，以及此前自行开发的 TRAE 适配|
|extension / desktop|本项目此前自行开发的 TRAE 桌面桥和项目窗口注册|

监督者与执行者的权限通过流程区分。执行端确认自身任务结束并给出真实结果；监督端独立检查后，通过 accept 保存验收意见与证据。返工保持原任务和原生会话，只更新轮次与结果位置。网关负责身份和记录，不代替模型判断项目是否优秀。

## 持久性与迁移

继续使用 hub_runs 和 hub_events 表、已有 JSON 任务字段及稳定任务 ID。新服务读取已有尝试身份后只协调和查询，不把历史 dispatching / running 当成新任务再次派发。未知原生状态保留容量占位，等待明确恢复理由及原生空闲证据。

实际迁移应先备份整个旧状态目录，在副本上检查表和 JSON 兼容性，再在无执行中任务的维护窗口切换。此轮只使用隔离测试数据库，没有迁移正在运行的旧服务。

## 服务生命周期

读取并验证 settings.json 后，以排他文件创建 service.lock。存活 PID 或不可核验的锁不会被覆盖。取得所有权后移除旧 connection.json；工作端报告服务、数据库和本机 HTTP 全部成功启动后，使用同目录临时文件与重命名发布连接信息。connection.json 只指向 tokenFile，工作台不会嵌入令牌。

任何中途失败都会关闭已经取得的报告服务、HTTP、原生连接和数据库，并释放自己的锁。停止会拒绝新轮询，关闭 HTTP 连接，等待已经进入的编排操作完成，再关闭持久资源；已经在桌面运行的任务与持久执行身份不会被主动删除或重新派发。

## 文件与本机接口

结果受大小、结构与路径边界约束，成果按真实路径和 SHA256 固定。验收和下载复核摘要，禁止把路径替换或链接逃逸后的文件当成原成果。HTTP 只监听 127.0.0.1，校验 Host / Origin，支持本地 Bearer 与严格同站 cookie。模型文本按纯文本呈现。

这些约束由源码和离线检查验证；不能据此宣称多台电脑或长期无人值守已经证明稳定。
